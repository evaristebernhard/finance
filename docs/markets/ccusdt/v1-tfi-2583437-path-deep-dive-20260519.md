## Why The Manager Cut It

The manager is designed to protect cases like `1615412`, `2377379`, and
`2361187`. For `2583437`, however:

1. The first meaningful release was real:

$$
R_{25.31}=H_{25.31}=38.62.
$$

2. The immediate drawdown was also real:

$$
R_{26.91}=20.30,\qquad D_{26.91}=18.33.
$$

3. But the post-drawdown state was not dead. From 27s to 30s, there were no
trades, but favorable queue imbalance came back:

$$
\mathrm{QI5}_{27,30}\approx0.936.
$$

4. Subsequent pulses from 35s, 40s, 48s, and 55s created the true payoff.

So the manager confused:

$$
\mathrm{first\ wave\ drawdown}
\quad\text{with}\quad
\mathrm{terminal\ decay}.
$$

## Implication

This case argues against a universal drawdown stop. But it does not invalidate
the small manager. It says the next minimal distinction is:

$$
\mathrm{drawdown\ with\ book\ dead}
\neq
\mathrm{drawdown\ with\ latent\ favorable\ queue\ still\ present}.
$$

A conservative future test should ask whether, at drawdown time:

$$
\mathrm{QI5}_t>q,\qquad \mathrm{trade\ notional}_{t-\Delta,t}\approx0,
$$

should delay exit for a short grace window. That is still a path/book geometry
rule, not a broad ML model.

Do not add this rule yet without checking that it does not re-open `1615412` and
`2377379`. This case is a warning label, not a permission slip to overfit.
